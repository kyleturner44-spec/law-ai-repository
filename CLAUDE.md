# CLAUDE.md - AI Assistant Guide

## Project Overview

**AI Use Cases for Law** is a React-based web application designed for law students to discover, share, and browse AI use cases relevant to legal education and summer work. The platform enables community-driven knowledge sharing with an admin approval workflow.

### Purpose
- Enable law students to share innovative AI applications in legal contexts
- Create a searchable repository of approved use cases
- Foster knowledge sharing about AI capabilities in legal practice

## Application Architecture

### Component Structure
The application is a **single-page application (SPA)** with all UI logic contained in `App.js`. It uses conditional rendering to display different views:

1. **Browse View** (`view === 'browse'`)
   - Default landing page
   - Search and filter approved use cases
   - Display use cases in card grid layout

2. **Submit View** (`view === 'submit'`)
   - Form for submitting new use cases
   - Fields: name, title, description, benefits
   - Submissions go to pending status

3. **Admin View** (`isAdmin === true`)
   - Password-protected admin dashboard
   - Manage pending submissions (approve/reject)
   - Manage approved submissions (delete)
   - Manage categories (add/remove)

4. **Admin Login Modal** (`showAdminLogin === true`)
   - Password authentication for admin access
   - Current password: `VAILL1!` (hardcoded in App.js:61)

### State Management

## Key Conventions for AI Assistants

### Code Style

#### React Patterns
- **Functional components only** - No class components
- **Hooks for state** - `useState`, `useEffect`
- **Inline handlers** - Define event handlers in JSX when simple
- **Conditional rendering** - Use ternary operators and `&&` for conditional UI
- **Component organization**:
  1. State declarations
  2. Effect hooks
  3. Handler functions
  4. Utility functions
  5. Return/render logic

#### Naming Conventions
- **Components**: PascalCase (e.g., `AIUseCaseRepository`)
- **Functions**: camelCase (e.g., `handleSubmit`, `loadCategories`)
- **State variables**: camelCase (e.g., `isAdmin`, `selectedCategory`)
- **Constants**: camelCase for local, UPPER_SNAKE_CASE for module-level
- **File names**: camelCase for utilities, PascalCase for components

#### JSX Formatting
- Use double quotes for JSX attributes
- Use single quotes for JavaScript strings
- Self-closing tags when no children: `<Component />`
- Multiline JSX wrapped in parentheses
- Keep className strings readable (one utility per logical group)

### Security Considerations

#### Current Security Issues
1. **Hardcoded admin password** in `App.js:61`
   - Password: `VAILL1!`
   - Client-side only - not secure for production
   - Should use Firebase Authentication instead

2. **Exposed Firebase credentials** in `src/firebase.js`
   - This is normal for client-side Firebase
   - Security enforced via Firestore Security Rules
   - Rules should be configured in Firebase Console

3. **No input sanitization**
   - User inputs directly stored in Firestore
   - XSS risk if rendering HTML (currently safe with React)
   - Consider sanitizing before display if adding rich text

#### Recommendations for Production
1. Replace hardcoded password with Firebase Authentication
2. Implement proper admin role-based access control
3. Add Firestore Security Rules to enforce permissions
4. Add input validation and sanitization
5. Implement rate limiting for submissions
6. Add CAPTCHA to prevent spam submissions
7. Use environment variables for Firebase config

### Firebase Best Practices

#### Reading Data
```javascript
// Good: Load once on mount
useEffect(() => {
  loadSubmissions();
  loadCategories();
}, []); // Empty dependency array

// Avoid: Multiple reads in render
```

#### Writing Data
```javascript
// Good: Async/await with error handling
const handleSubmit = async () => {
  try {
    await addDoc(collection(db, 'submissions'), data);
    loadSubmissions(); // Refresh after write
  } catch (error) {
    console.error('Error:', error);
    alert('Error submitting.');
  }
};

// Avoid: Unhandled promises
```

#### State Updates After Database Operations
Always reload data after mutations:
```javascript
await addDoc(...);
loadSubmissions(); // Refresh list

await deleteDoc(...);
loadSubmissions(); // Refresh list
```

## Common Issues & Solutions

### Issue: Tailwind classes not working
- **Cause**: Tailwind loaded via CDN - any custom config ignored
- **Solution**: Either continue with CDN or switch to npm package with config

### Issue: Firebase permission denied
- **Cause**: Firestore Security Rules not configured
- **Solution**: Configure rules in Firebase Console to allow read/write

### Issue: Admin password not working
- **Cause**: Hardcoded password in App.js:61
- **Solution**: Check `handleAdminLogin` function for current password

### Issue: Submissions not appearing
- **Cause**: Status is 'pending', only 'approved' shown in browse view
- **Solution**: Use admin panel to approve submissions

### Issue: Build fails
- **Cause**: Various (check error message)
- **Common fixes**:
  - Clear node_modules and reinstall: `rm -rf node_modules && npm install`
  - Clear cache: `npm cache clean --force`
  - Check Node version compatibility
